# 胡闹运动会（线上版）

桌游《胡闹运动会》（Magical Athlete）的多人实时网页版：2 轮蛇形选秀组队，4 场赛跑，36 名技能各异的运动员互相使坏。公开房间列表一键加入、房间码联机、AI 补位、全 AI 自动对局观战、断线自动托管，手机竖屏自动切换方格赛道。

当前是可玩的联机试玩版，按 3-6 名选手（含 AI）开赛。两位真人玩家可以加 1 名 AI；实体版的双人双运动员变体尚未实现。狂野赛道布局和递增计分采用本试玩版设置，具体差异见文末。

## 语音开麦

房间大厅、对局顶栏都有麦克风按钮，点一下开麦、再点闭麦（自由说话，不用按住）。观战房的观众同样可以开麦聊天；对局「更多」里的耳机按钮可单独关掉语音收听。同一房间最多 6 人同时开麦。

```
浏览器A ──（/ws 转发 SDP / ICE 信令，消息类型 voice、rtc）── 浏览器B
   └──── 音频 WebRTC 直连（Opus），直连不通时经 TURN（coturn）中继 ────┘
```

- 两人里有一方开着麦才建立连接，都闭麦 20 秒后断开；开闭麦只替换发送轨道，不重新协商。
- 服务端不碰音频，只按「标签页连接 id」在同房间内转发信令（`server/hub.js` 的 `relaySignal`），并清洗字段、按连接限频。
- TURN 用 coturn 的 `use-auth-secret`：游戏服务按 `HUNAO_TURN_SECRET` 现签 24 小时有效的临时用户名/密码随语音名单下发，前端看不到密钥。不配置时只靠浏览器直连（同一局域网可用，手机 4G、公司网络常常连不上）。
- 浏览器只在 https 或 localhost 下给麦克风权限：用 http 访问其他机器的地址时只能听不能开麦。
- TURN 用环境变量配置：`HUNAO_STUN_URLS`、`HUNAO_TURN_URLS`、`HUNAO_TURN_SECRET`（密钥与 coturn 的 `static-auth-secret` 相同），服务启动日志里的「语音中继」一项显示是否读到。

## 本地开发

```bash
npm install
PORT=8096 npm start  # 直接用 Node 同时托管静态资源和 WebSocket，默认 0.0.0.0:8096
npm test             # 规则语义、1000 局模拟、房间生命周期、HTTP/WebSocket 回归
npx playwright install chromium  # 首次运行浏览器测试前安装
npm run test:frontend # 假 WebSocket 异常路径 + 真实 WS 目录／观战回归
npm run test:browser-helper # 真实握手、提交确认、重定向防护及资源清理
npm run test:browser  # 单人四场完赛，必须显示总冠军
npm run test:multi    # 桌面 + 手机联机、重连、横竖屏、四场同步与重开
npm run test:spectator # 双观众全 AI 自动四场，刷新／横竖屏、同局成绩及再看一局
npm run test:directory # 真实首页目录：自动更新、一键加入、直接观看及离场清理
npm run test:voice-browser # 两个 Chromium 假麦克风：开麦连通、说话检测、断线恢复、闭麦与离房清理
npm run test:all      # 完整验收
```

零前端构建，服务端只依赖 `ws`，所有状态在内存里（重启服务会清空房间）。Playwright 仅为开发测试依赖。

浏览器测试默认启动 `127.0.0.1` 随机端口的隔离后端，不使用线上房间，结束后关闭连接与计时器。可用 `W` / `H` 设置单人测试尺寸，`OUT` 设置截图目录，`CHROMIUM_EXECUTABLE_PATH` 指定本机 Chromium 路径。只有明确要测试已有服务时才传 `BASE`；远端地址还需显式设置 `ALLOW_REMOTE=1`。`test:directory` 固定只运行随机 loopback 隔离后端，不接受 `BASE` 或远端开关。整局验收默认使用 `SEED=9`，可指定其他非负 31 位整数复现不同规则组合；随机覆盖由 `test/sim.js` 单独承担。完整对局可能需要数分钟，`MAX_MS` 超时会判定失败，而不是打印未完成状态后返回成功。动作成功只按带 `gameId/id/value` 的服务端 `ack` 统计；比分按席位、姓名及四场完整成绩核对，不把超时托管完赛等同真人操作通过。

## 首页公开房间列表

首页「公开房间」实时列出仍有成员在线的房间，不需要先输入房间码：

- 普通等待房间点击「加入」进入大厅；显示房主昵称、真人／AI 席位及在线人数。满 6 席但含 AI 时，加入可替换一个 AI。
- 全 AI 房间点击「观看」直接加入原对局，只增加观众，不占参赛席或另开比赛；显示观众人数及在线人数。
- 已开赛或已结束的普通房间仍可展示，但非原成员不能加入；原成员可返回自己的房间。
- 建房、加入、开赛及离场会自动更新目录；也可点「刷新」。断线时保留上次列表作为参考，按钮不可点击，重连后重新获取。
- 无人在线的房间不进入公开目录；暂时断线的原成员仍可凭原身份／邀请返回。公开目录只含房间摘要，不包含身份凭证、参赛者 ID、对局编号或手牌。

房间码及邀请链接仍然可用。协议为无参数 `listRooms` 请求及 `roomList` 回复；目录消息只更新列表，不切换当前页面或改变比赛。

## AI 自动对局与观战

首页点击 **「观看 AI 对局」**，默认由 4 名 AI 参赛，可选择 3–6 名。AI 自动完成选秀、每场出战、掷骰及技能选择，直到四场结束；你是观众，不占参赛席位，也不需要开启托管或提交动作。

- 发起观战的房主可切换 1x／1.5x／2.2x 速度；结束后点击「再看一局」在原房间直接开始新的全 AI 对局。
- 可以把观战房间码或邀请链接发给朋友，他们加入后也只观看，不会替换 AI。
- 刷新会恢复原观战身份及对局；所有观众断线时暂停推进，重新连接后继续。所有观众主动离开时清理房间。
- 观众不能提交选手动作、开启托管或修改 AI 的选牌。观战房主离开／离线后，控制权限优先移交在线观众。
- 普通真人联机房间保持原有规则，不开放陌生人在已开始的对局中旁观。

观战使用现有规则引擎的启发式 AI，不需要模型服务或 API Key。观众看到的是与真人对局相同的逐步比赛动画，而不是一次性展示最终结果。

## 玩法流程

1. 首页输入昵称 → 「和 AI 开一局」（可选 2-5 个 AI 对手），或「创建房间」把房间码/邀请链接发给朋友
2. 房主在房间里加 AI、开始比赛（3-6 人）
3. 选秀：两轮蛇形选秀，每人 4 名运动员
4. 每场所有人同时暗选出战运动员 → 亮牌 → 轮流掷骰、触发技能 → 两人冲线即结束
5. 四场结束总分最高者获胜

HTTP 页面无法自动复制时，「复制邀请链接」会显示可全选的链接输入框，使用长按或 Ctrl/Cmd+C 手动复制即可。

## 规则实现要点

卡牌文字没写清楚、有几种理解的情形统一记在 [docs/规则口径.md](docs/规则口径.md)；`test/cards/` 按卡牌原文逐句写了测试，名字以 `[口径]` 开头的用例按那份文档的结论断言。

- 规则与 36 张技能卡文字依据 CMYK 官方英文规则书（2025 版）逐张翻译实现。
- 同时触发的顺序：赛道格 → 当前玩家 → 其他玩家顺时针；「超过」「瞬移不算移动」「移动 0 不算移动」等术语严格按规则书。
- 无限循环（如蹭蹭狗撞巨婴）：同一技能在完全相同的局面下再次触发即判定为循环，走完一遍就停（规则书第 8 条）。
- 服务端权威：前端只播放事件动画，播完再用快照校正；动画期间不提前显示结果。
- AI 与超时托管按动画时长节奏推进；房主可以把全房动画调到 1.5x / 2.2x。
- 每次开局有独立 `gameId`；网络动作必须同时匹配对局编号、决策编号和合法选项，旧房间或上一局的迟到动作不会影响新局。
- 手动托管、超时托管与在线状态分开记录；其他成员重连不取消托管、不延长已发放的思考时间。房主离线或离场时优先移交给在线成员。
- 前端全量恢复、退房及回大厅会取消旧动画；断线不补发旧动作，重新同步后按权威局面操作。新前端在后端升级前仍兼容没有 `gameId` 的旧协议；新后端严格拒绝缺少对局编号的动作。
- 模仿猫的并列领跑由玩家选择；同回合连锁不重复询问相同领跑组合，后续回合可以重新选择。有效技能同步到行动卡和玩家栏。
- 达到回合／循环保护上限的场次会明确提示并记录 `reason`，保留已有得分进入结算，不冒充自然冲线完赛。

## 与实体版的规则差异

- 试玩版每场金/银牌分值为金 3/4/5/6、银 1/2/3/4。现有实现未完整核实实体版四场奖牌的数值，后续核对后可修改 `game/tracks.js` 的 `GOLD` / `SILVER`。
- 狂野荒原的特殊格布局是自行设计的（规则书没有给出完整赛道图），在 `game/tracks.js` 里调整。
- 2 人变体、3 人双运动员变体暂未实现（2 人可加 1 个 AI 凑成 3 人）。
